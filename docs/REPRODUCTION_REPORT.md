# 보안 Agent 「케셰브」 22단계: 새 환경 재현 및 릴리스 기록

이 문서는 22단계 「최종 커밋의 새 환경 재현과 릴리스 기록」 결과 보고서입니다.  
기존 작업 폴더를 완전히 보존한 상태에서, 별도의 격리된 새 폴더에 Git 원격 저장소를 새로 복제(`git clone`)하여 실행 설명서([docs/STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md))의 절차대로 재현하고 관찰한 결과를 기록합니다.

---

## 1. 저장소 정보 및 새 환경 복제 절차 (이동 가능한 구성)

- **원본 작업 폴더**: 보존 완료 (기존 소스 및 Git 이력 그대로 유지)
- **저장소 주소**: `https://github.com/stulss/choi-bujang-secret-vault.git`
- **기준 브랜치**: `main`
- **최종 기준 커밋**: 이번 22단계 최종 단일 커밋 해시 (제출 시 HEAD)
- **외부 설정 및 비밀값 배제**:
  - 로컬 절대 경로나 비밀값에 의존하지 않으며, 설정 견본([`.env.example`](../.env.example) 및 [`on-client/.env.example`](../on-client/.env.example))을 제공합니다.
  - 외부 인증 자격 증명(인증서, 접속 암호, API 인증 키)은 코드·문서·Git에 포함되지 않습니다.

### 새 환경 복제 및 실행 절차
```powershell
# 1. 기존 프로젝트 밖의 새 빈 폴더 준비 및 복제
git clone https://github.com/stulss/choi-bujang-secret-vault.git "reproduction-test"
cd "reproduction-test\on-client"

# 2. 문법 및 런타임 확인
node --version    # v24.19.0 확인
npm --version     # 11.17.0 확인
npm run check     # node --check student/extension.mjs 통과

# 3. 예제 모드 실행 및 진단 조회
$env:ON_PORT = "5195"
node src/server.mjs --demo
# 브라우저 또는 curl: http://127.0.0.1:5195/api/diagnostics

# 4. 기본(연결 확인) 모드 실행 및 종료
$env:ON_PORT = "5196"
node src/server.mjs
# 종료: Ctrl + C 또는 포트 조회 후 프로세스 종료
```

## 4. 데이터 보존 계획 (학생 데이터 보존·백업·복원)

- **보존 대상 데이터**:
  - 로컬 브라우저 상태: 브라우저 캐시 및 로컬 스토리지에 저장되는 사용자 UI 설정값.
  - 앱 서버 상태: `on-client` 런타임 메모리 상태 및 로컬 설정 파일([`.env.example`](../.env.example) 기준 작성된 로컬 환경 파일).
  - Git 버전 이력: 1~22단계 누적 커밋 및 태그 기록 전체.
- **백업 절차**:
  1. Git 원격 저장소(`origin/main`) 푸시를 통한 소스 및 문서 형상 관리 백업.
  2. 로컬 설정값 및 검증 스크립트 산출물은 프로젝트 외부 별도 디렉터리(`projects/submissions`)에 JSON 형식으로 보존.
- **복원 절차**:
  1. `git clone`으로 새 환경에 소스 코드를 복원.
  2. [`.env.example`](../.env.example)을 복사하여 대상 환경에 맞는 포트 및 경로 재설정.
  3. `npm run check`로 복원 코드의 문법 무결성 검증 후 서비스 재기동.
- **데이터 보존 한계 및 제약**:
  - 로컬 앱 서버(`server.mjs`)는 인메모리 상태 중심이므로 프로세스 종료 시 세션 상태가 초기화됩니다.
  - 외부 연동 자격 증명 및 임시 세션 토큰은 영구 저장하지 않으므로 복원 시 재인증/재인가가 필요합니다.

## 5. 시연과 학생 진술 구분

- **시연(Demo) 모드**: `npm run demo` 실행 시 반환되는 모의 사용자, 앱 목록, 가상 보안 이벤트는 학습 및 동작 구조 검증을 위한 가상 데이터입니다. 실제 운영 서버의 결과가 아닙니다.
- **학생 진술(Student Observation)**: 본 문서의 재현 관찰 결과(2절)는 학생이 로컬 PowerShell 환경에서 직접 명령을 실행하여 관찰한 사실만을 진술한 것입니다.
- **AI 원문 검토와 실행 검증의 구분**:
  - 포털의 AI 검토 통과는 **제출된 커밋의 문서와 코드가 일치한다는 정적 원문 검토 기준의 통과**를 의미합니다.
  - 서버나 AI가 원격에서 학생 코드를 직접 실행하거나 새 환경에서 재현하여 검증한 것이 아니며, 이를 "실제 운영 환경 검증 완료" 또는 "v1.0 자동 인증"으로 왜곡하지 않습니다.

## 6. 버전 및 지원 범위

- **현재 버전**: `v1.0-rc1` (검증 중인 릴리스 후보 버전)
- **지원 환경**: Windows 11 Home (x64) + Node.js `v24.19.0` + npm `11.17.0`
- **미지원 및 미확인 환경**: macOS, Linux 배포판, Node 22/23, PowerShell 7 (테스트되지 않음)
- **알려진 미해결 사항**:
  1. 19단계 실제 시스템 보안 조치(세션 차단, 네트워크 격리 등)의 실제 집행 연동은 플랫폼 차원에서 미제공 상태입니다.
  2. 외부 ALEPH SDP 호스트 및 라이브 AI 게이트웨이 연동은 운영 측 인프라 준비가 필요합니다.
